原十题全部保留，但Anko单列为v1过渡题：只读承接第三批B1正式失败（F2P 0/2）、H1正式成功（2/2）及同一份完整/压缩初始Hint，不重跑B1/H1；B从B2继续，I从自己的首轮独立开始。第三批M1学生虽已完成并保存补丁，但用户在正式评测完成前取消，成绩为NA，不纳入独立M成功或失败统计。其实际消耗仍保留。Anko不补跑M，也不进入其余九题的v2 H/M比较；这项事后过渡不能用来证明共享首轮或教师记忆的因果效果。

其余九题固定采用v2：每题实际H首轮标记 `shared_with=['H','M']`，H/M共用这一次学生响应与成绩。共同首轮成功时两种策略均结束，M记忆机制未触发；保留原H对成功轨迹的一次共同诊断复盘，检查Hint使用与泄漏标记，成本单列 `HM/shared_success_review`，不再执行M学生或M续会话复盘。共同首轮失败时，H新教师与M原初始教师分别复盘同一份轨迹/补丁/正式结果，再执行各自全新的H2/M2。共同首轮计入两种策略各自的五轮上限，每条分支最多再执行四轮。

每个实际学生尝试都从初始代码和新学生会话开始，在该会话内可多次读写文件和运行测试；达到提交、时间上限或异常时结束。下一次尝试重置代码与学生会话，仅迁移语言指导。除明确共用的H/M首轮外，各组不传递学生代码或后续轨迹。B与I各自最多五次，通过即停止。原框架baseline默认只尝试一次，本次配对驱动显式安排至多五次，另保留原脚本默认行为。

每题初始完整Hint与首次压缩仍只实际生成一次，供H/M/I使用；Anko引用第三批已有产物，其余九题重新生成本题Hint与初始教师会话。成本按实际调用来源计一次：第三批用量（含取消M1）保留在原来源，第四批只计新增调用；承接结果与Hint不重复计费。共同首轮成本计一次，共同成功诊断复盘成本计一次。按策略分摊仅作展示，不能再加入实际总量。

报告分别呈现Anko v1过渡与九题v2。v2的H/M总体曲线须说明首轮成功来自同一观测、不能当两个独立样本；教师会话差异的后续比较使用“共同首轮失败”的配对题集，并列出分母及M机制未触发数。第一、二批结果不承接、不与第四批拼接为同一十题实验。

I 的教师可见题目、GT、已有 Hint 与截至检查点的学生轨迹，不能给出可直接应用的补丁、完整实现、逐步答案或隐藏测试。每次候选指导经过原压缩模块扩展出的筛查，实际发送最多 100 个英文词。不发送 Hint 也消耗检查次数。每次检查连同筛查限时 600 秒。自动筛查并不构成不存在答案泄漏的证明，原始候选、筛查与发送文本均保留供复核。

## 固定配置

- 所有学生、教师、压缩器、筛查器及 SDK 辅助模型均路由至 `gpt-6.1-terra`，思考强度 `low`。
- 模型由本机 Codex CLI 登录调用，未使用 Ofox API，也不自动切换模型或购买额外额度。
- 保留 Claude Agent SDK 的工具定义与实际执行路径。Codex 仅返回动态工具请求，原 SDK 在隔离容器执行，再将工具结果返回同一个 Codex 会话。兼容层按已到达的工具请求批次交付，可能与原 API 的并行批次边界不同，四组采用同一策略。
- 禁用 Codex 原生文件、命令、搜索和其他环境工具。若出现原生工具执行或无法维持工具执行隔离，停止实验；不改成原生 Codex 解题来替代。
- 原框架学生提示、题目包装、GT Hint 生成、压缩与复盘流程继续复用。仅将相关模型提示统一成英文，并增加会话续接和检查点所需接口。代码、命令和工具原始输出不翻译。
- 一次仅运行一个学生工作流。隔离虚拟机 8 vCPU；学生容器 8 CPU、128 GiB；教师同为 8 CPU、128 GiB；评测容器 8 GiB，使用该虚拟机可用的 CPU。
- 学生有效执行上限 7200 秒，扣除轮内教师等待；完整墙钟时间和教师等待分别记录。初始教师上限 3600 秒。
- SDK 固定 `claude-agent-sdk==0.2.186`，捆绑原生 CLI `2.1.329`，LiteLLM `1.81.8`。所有新学生/教师容器共用只读预装 Python 运行环境；实际版本见 `preflight/`。任务安装命令仍来自原数据。
- 任务 10 道，固定采用原任务版本与正式评测，不重新抽题。没有设置模型随机种子，不能将单批结果解释为无随机误差的因果结论。
- 正式隐藏评测在提交后运行，轮内教师不访问正式隐藏评测结果。外层复盘仍沿用原框架读取本次正式结果的方式。
- 额度不足或持续限流时保存轨迹、补丁、调用记录与停止原因，整批停止；不自动恢复。异常未完成的尝试单列，不当作正常评测失败。
- 本批没有训练或微调；不会将有 GT 教师辅助下的成绩解释为模型已经学会独立解题。去教师/DeHint 泛化测验需要另行实验。

`source/run_codex_experiments.py` 使用 `--stage integration` 或 `--stage formal`，并要求新的 `--experiment_name`。第四批通过 `--shared_first_attempt` 与显式 `--continue_from` 承接已停止第三批的指定产物；这不恢复旧学生或旧主进程，也不自动重试取消的M1。具体参数及验证见第四批冻结配置；本次80项离线测试通过，运行环境与新服务状态检查通过，冻结点尚未开始模型调用。`--dry_run` 只检查编排，不产生实验成绩。

目录：

- `source/`：原源码副本及本次修改。
- `tests/`：兼容协议、教师检查点、配对编排与统计测试。
- `preflight/`：实际版本、资源、CLI/SDK 联调证据。

- `vm/`：新虚拟机磁盘覆盖层、运行依赖与本次进程信息。

Token 以 Codex 实际返回值记录；缓存输入是输入的子集，推理输出是输出的子集，不能再次加到总量。未返回的统计保留为空，不伪造费用折算。本目录不新增文件哈希验证。

## 兼容边界

原 SDK 的工具调用与会话继续复用；后端传输协议改为 Codex app-server 的动态工具协议，并非直接转发原 API 请求。原脚本仍传送 `temperature`、`max_tokens` 等字段，但本兼容层没有将这些字段映射成 Codex 原生推理参数；实际推理强度固定为 low，其余采用该 CLI/模型的默认行为，不能声称这些旧 API 参数已生效。后续四组使用同一实现。

Codex 宿主不可直接访问任务工作区。兼容层会统一用英文说明，原 SDK 的动态工具在独立任务容器执行，仍遵守各自原角色和实际工具返回的权限；教师仓库保持只读。此说明用于避免把宿主权限误当成学生工具权限。

SDK 汇总里可能显示零 Token，实际消耗必须以 `logs/bridge/token_usage.jsonl` 的模型增量为准。Codex Turn 的时间包含外部工具等待，API 请求耗时是分批请求耗时，均另行命名，不冒充纯模型计算时间。

在本次已经启动的隔离环境中，入口示例为：

```bash
/srv/lab-disks/disk2/users/xymo/hint-baseline-run/env/bin/python -B \
  /srv/lab-disks/disk2/users/xymo/hint-codex-experiments/source/run_codex_experiments.py \
  --stage integration --experiment_name new_integration_name
```

正式入口将 `--stage` 改为 `formal` 并采用新的实验名。已有实验名会拒绝覆盖；获授权的第四批承接使用新的运行目录和来源标签，不覆盖第三批。虚拟机与本机服务的 PID、完整启动参数分别保存在 `vm/vm-state.json`、`vm/ssh-tunnel-state.json`、`logs/services.json`；它们的存在不代表进程仍在运行，当前状态以实际检查与报告为准。

本机模型服务端口为 8765、轮内教师服务为 8766，均绑定本机回环地址。通过本次 SSH 连接映射到隔离虚拟机；容器用 `172.17.0.1` 访问。Docker 连接仅使用本目录的 `vm/docker.sock`。

Codex 的内部思考不伪造成 SDK 的 thinking block；教师复盘与轮内观察以实际可见响应、工具请求和工具结果为准。内部推理 Token 若模型返回会单独记录，未返回则为空。泄漏审查也只能覆盖已保存的可见轨迹，不能据此证明内部思考没有引用指导。

若一个并行工具批次跨过检查阈值，轮内检查会等待该批次完成；下一次检查从本次实际完成数再计至少20个主工具，避免紧接着补发多次提醒。

本次虚拟机使用 TCG CPU 仿真，8 vCPU 与容器 8 CPU 额度并不表示独占8个物理核。四组统一此配置并串行运行；共享主机负载仍可能影响墙钟速度。环境预检和镜像准备只在联调时交错，正式阶段会先结束这些辅助工作。

本目录 Token 报表的范围是实验程序经模型桥和独立探针实际记录的调用，不包含本聊天的实现、监控对话或其他 Codex 任务。账户额度百分比可能同时受其他会话影响，不能直接当作这批实验的货币账单。

第四批首次启动在模型调用前因承接取消记录的目录前缀错误退出（0 Token、无实验状态）。已修正命名、用真实第三批文件验证B1/H1与Hint只读承接，并通过80项离线测试；原预启动冻结和错误保留在 `preflight/formal_04_constructor_failure/`。正式执行使用修正后重新冻结的版本。
