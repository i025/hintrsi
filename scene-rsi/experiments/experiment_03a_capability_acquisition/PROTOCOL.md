## Frozen conditions and information

A0 has the original base student and no library. A1 learns from the same three development task descriptions/reference RGB images, prespecified goals and teacher prior, without historical student code/trajectory/candidates or GT. A2 adds all E3 runs, A3 all E4 runs, each with the same three development scenes and two repetitions, matched types of actual tool events, source captures, saved student states and guidance. They receive no full GT. A4 receives the three actual development Blender GTs but no historical student trajectory. A5 receives the exact A4 GT and exact A3 exploration evidence. Additional information is the variable; file/Blender tools, generation and validation opportunity are shared. No pooled all-group candidate knowledge is fed to a source-specific learner.

Primary capability goals are spatial relations/orientation/layout and material/texture appearance. Geometry verification is auxiliary. The common interpretation boundaries include preserving assembly/hinge/opening relations, distinguishing near-zero support gaps from contact proof, checking actual output-connected material nodes, and separating illumination from surface properties. These are prespecified research questions, not a fixed reconstruction algorithm or supplied solution. GT is one implementation; hidden geometry, absolute scale and symmetric orientations are not uniquely identifiable from a single image.

Every role uses the existing Claude Agent SDK loop and current verified Codex CLI model-only bridge, gpt-6.1-terra / low. SDK owns Bash/Read/Write/Edit/Glob/Grep and context; CLI native agent does not own student tools. All experiment model operations use this boundary. Current Bridge includes the earlier timeout cancellation and internal-agent-disable changes. Model flags, messages, actual image attachments, tools and usage are retained; a configured model name is not an independent provider-weight attestation.
