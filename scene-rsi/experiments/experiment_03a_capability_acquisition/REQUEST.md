## 2. 总体研究目标

我们的最终目标是在基础模型固定的条件下，使 Scene Agent 自主发现能力缺陷，通过教师知识、GT、自然轨迹和主动探索经验，持续获得可迁移的三维重建能力。

已有实验发现：

- 自然重建轨迹具有不同程度的策略重合。
- 相同模型的不同轨迹也包含互补建模技术。
- 学生可能在关键缺陷没有解决时结束任务。
- 教师具体 Hint 可以改变学生实际采用的建模和验证方法。
- 更详细的教师指导不一定获得更好的重建结果。
- 主动探索已经产生真实候选程序和可执行几何检查方法。
- 目前没有证明这些经验具有长期跨场景迁移价值。

用户观察现有真实重建结果后认为，影响整体恢复度的主要问题是：

1. 物体之间的相对位置。
2. 物体朝向。
3. 整体空间关系和比例。
4. 材质、贴图与外观恢复。

细微悬空、部件支撑和连接关系仍然重要，但不应因为它们容易客观测量，就将其作为唯一主要研究目标。

上述人类意见是针对当前有限案例的初步观察，不是所有场景的固定评价权重。

学习的是可迁移方法，而不是复用参考答案。

# Part A：Experiment 03-A — Capability Acquisition

## A1. 研究问题

研究不同知识来源能否产生不同程度的长期、可迁移重建能力。

重点能力：

1. Spatial-Relational Reconstruction：位置、朝向、比例、布局、遮挡和相机联合推理。
2. Appearance Reconstruction：材质、贴图、纹理方向、尺度、映射、光照与材质分离。
3. Geometry Verification：部件连接、物体支撑、碰撞及修复后的几何验证。

第一、第二类是主要研究对象，第三类作为辅助研究和客观验证案例。

## A2. 六个实验组

### A0：Base Student

原始学生。

不提供额外知识库、Skill、Tool 或教师 Hint。

### A1：Teacher Prior

教师根据共同开发任务描述、参考图、预先冻结的能力问题及自身知识生成能力库。

不读取真实学生代码、执行轨迹、完整 Blender GT 或探索候选结果。

用于研究教师本来能够提供什么知识。

### A2：Strategy-Trajectory Learning

教师读取 Experiment 02 的 E3 普通策略指导轨迹。

包括两次重复中的实际 Hint、学生操作、代码、检查程序、成功和失败经验、验证结果。

不读取完整 GT。

### A3：Exploration-Trajectory Learning

教师读取 Experiment 02 的 E4 主动探索轨迹。

包括实际候选技术、候选代码、执行结果、失败原因、比较过程、学生最终选择及修复验证。

不读取完整 GT。

A2 和 A3 尽量使用相同场景、相同重复数量、相同信息类型及相同知识生成预算。

### A4：GT-Guided Learning

教师访问共同开发任务资料和三个完整 Blender GT。

通过直接检查真实参考场景，发现重建技术、结构关系和材质构造知识。

不读取历史学生执行轨迹或探索候选结果。

### A5：GT + Exploration Learning

教师同时使用与 A4 相同的完整开发集 GT，以及与 A3 相同的主动探索轨迹。

重点分析：

- GT 中存在但学生轨迹没有采用的技术。
- 学生探索中出现的不同于 GT 的合理实现。
- GT 与探索经验共有的结构约束。
- 不同实现方法的适用条件。
- 如何利用真实执行验证弥补参考解与学生行为之间的信息差异。

不要假设 A5 必然最好。

各组应尽量共享相同的开发任务范围、能力目标、基础模型和知识生成预算。

实际输入 Token 差异、调用成本及 GT 检查成本需要单独记录。

A5 同时拥有两种信息来源是实验变量，不要额外为它增加独有的工具权限或验证机会。

## A3. 能力表示

不能重复之前代码题实验中仅生成数百词通用指导文本的做法。

A1–A5 均允许构建：

- 可读 Skill 文本。
- 可执行 Blender Python 函数。
- 实际检查工具。
- 材质生成工具。
- 空间关系分析工具。
- 适用条件与失败边界。
- 经过验证的示例。
- 实际证据记录。

每个能力单元应包含：

Capability Name  
Applicable Conditions  
Problem and Technical Hypotheses  
Executable Method  
Verification Method  
Failure Conditions and Side Effects  
Evidence and Knowledge Origin

实际提供给学生的可执行能力与研究证据文件分开。

证据中可以保留原开发场景实例参数，但实际学生能力不得包含旧任务答案、原始 GT 资产或只对某个场景有效的固定坐标。

不要要求每组必须机械产生相同数量的函数。

但各组应具有统一的能力库文本长度上限、代码规模上限、工具调用权限、知识生成时间与验证机会。

具体预算在正式学习前冻结。

不能只有 A3 或 A5 允许生成可执行工具。

## A4. 重点研究空间关系能力

研究怎样将参考图像中的物体关系转化为可执行三维关系。

可以探索：

- 显式语义物体和部件标识。
- 物体局部坐标系与语义朝向。
- 相对位置、相对距离及尺度约束。
- 面向、背向、平行、垂直等关系。
- 参考视角中的投影中心、轮廓、可见面积和遮挡。
- 相机变化与真实物体布局变化的区别。
- 整体物体变换与部件内部变换的区别。
- 门轴、门板、门框等关系的一致维护。

这些是研究范围，不是要求教师采用某一套人类预定义算法。

特别分析 Experiment 02 的卧室门板反例：

E2-R2 的门板投影 IoU 达到约0.767，但实际源码中门轴被移动，而原门洞表示仍留在后墙。

不能直接将这种高 IoU 修复方案学习为有效通用能力。

需要从中学习如何同时维护图像一致性与三维结构关系。

如果当前轨迹无法支持可靠的空间关系方法，应保留失败证据，并利用开发集补充实际执行验证，不要虚构已经掌握的能力。

各学习组拥有相同的补充验证机会。

## A5. 重点研究材质与贴图能力

真实分析开发场景中的材质差异。

研究：

- 材质名称与实际节点实现的区别。
- 木材、石材、金属、布料和玻璃等不同表面的表示。
- 纹理坐标、方向和空间尺度。
- 程序化纹理与图像纹理。
- 基础颜色、粗糙度、法线和几何纹理的区别。
- 贴图与灯光、高光、阴影之间的混淆。
- 纹理是否真正绑定到目标物体。
- 纹理资源是否完整、可复现和可编辑。

结合 Experiment 02 的厨房 E4 真实候选进行分析。

教师提出过程序化颜色、图像纹理和粗糙度变化三种方法；学生实际执行了相关比较。

但这些方法只获得了有限的局部改善，没有证明某种方法普遍最优。

知识应当包含具体实现、适用条件和验证方法，而不是简单规定所有表面都使用 Noise 或图像贴图。

## A6. 保留几何检查能力

利用 Experiment 02 已有的 contact_check.py、check_chairs.py 和实际测量记录。

尝试抽象为不依赖特定椅子名称、固定世界坐标和平坦地板假设的检查方法。

至少区分：

- 明确的正支撑间隙。
- 近零间隙。
- 可能穿入。
- 支撑表面无法确定。
- 部件连接和整物体支撑。

不能将包围盒重叠或近零间隙直接当作完整物理接触证明。

## A7. 能力验证与冻结

所有知识生成完成后，在开发任务和预先留出的 Selection 任务上实际检查工具是否运行、方法是否适用以及是否引入明显副作用。

记录全部候选，包括未通过验证的能力。

各学习组使用相同验证预算。

如果能力库无法执行，可以依据共同规则在正式测试前进行修复或淘汰，记录原因。

正式测试前冻结各组能力库。

检查实际学生模型请求，确认相应知识已经进入学生上下文，并且工具真实存在、能够调用。

不允许根据最终测试结果修改已冻结的能力。

## A8. 独立新场景重建

优先完成四个新场景 × 六组，共24次独立重建。

学生从空白工作区和新参考图开始，而不是继续修复 Experiment 01 或 Experiment 02 的旧场景。

所有测试学生使用：

- 相同基础模型。
- 相同 reasoning effort。
- 相同基础 Prompt。
- 相同 SDK 和 Bridge。
- 相同基础工具和渲染环境。
- 相同初始时间及模型调用预算。
- 全新独立会话。

除各自冻结能力库外，不提供任何在线教师、任务特定 Hint、GT 或历史学生场景。

学生可以自主决定是否以及何时使用新增能力。

不要强制调用 Skill 以制造能力采用证据。

优先沿用每次25分钟、120次 Bridge 请求的上限。如果需要调整，必须在正式运行前统一调整。

保留全部轨迹、代码、Blender 场景、渲染、实际能力调用、耗时和失败。

## A9. 测评

分别报告以下指标，不强行合成为单一分数。

### 空间与朝向

- 可见物体识别及语义对应。
- 物体投影中心误差。
- 可见轮廓或实例掩码重合。
- 可辨识物体的相对朝向。
- 物体之间的相对位置、比例和遮挡关系。
- 相机与布局变化。
- 几何结构一致性。

必要时建立语义物体对应关系。

对重复实例、旋转对称物体和单图不可辨识关系明确记录不确定性。

只有可靠对齐坐标系、尺度和语义对应之后，才报告三维位置或角度误差。

将二维一致性与三维合理性分别评价。

### 材质外观

- 材质类别与视觉表现。
- 纹理方向、尺度、覆盖和对比度。
- 局部区域恢复度。
- 实际节点和纹理绑定。
- 纹理资源完整性。
- 材质与光照混淆。

尽可能提供统一条件下的辅助对照渲染，并说明残留混杂因素。

不要仅因为节点数量增加或者使用了复杂材质，就认定外观改善。

### 几何验证

- 支撑关系。
- 明显悬空。
- 部件连接。
- 可确认穿插。
- 修改引入的新问题。

### 整体质量与学习行为

- 独立匿名视觉评价。
- 参考图与真实渲染对照。
- SSIM 等辅助指标。
- 技术执行和交付完整性。
- 可复现性。
- 学生是否真正采用了所学习的方法。
- 采用能力后是否获得实际改善。
- 是否出现其他能力退化。
- 模型调用、Token 和运行成本。

自动评价不能冒充人类评价。

教师、学生和自动评价者使用同一个模型产生的相关判断偏差必须明确披露。

## A10. 科学分析

重点比较：

A1 vs A0：教师先验的价值。

A3 vs A2：主动探索轨迹相对于普通策略指导轨迹的价值。

A4 vs A1：完整 GT 的额外价值。

A5 vs A3：GT 对主动探索的补充价值。

A5 vs A4：主动探索是否提供了单一参考实现以外的有效知识。

同时分析：

- 不同能力库是否实际生成了高度相似的知识。
- 是否再次出现代码题实验中的知识冗余。
- 学生是否实际采用新增能力。
- 可执行工具是否比单纯文本提醒更容易产生有证据的行为变化。
- 哪些知识只是教师原有知识的具体实现。
- 哪些知识来自 GT。
- 哪些知识来自真实轨迹或新执行经验。
- 哪些方法仍然未经验证。

当前只进行一轮能力获取和迁移实验，不宣称已经证明持续递归能力增长。

# Part B：Experiment 03-B — Human-Aligned Teacher

## B1. 工程目标

构建一个可以独立于 RSI 使用的场景分析教师系统。

给定参考图和重建图，教师能够：

- 评价整体恢复度。
- 自主发现重要视觉缺陷。
- 定位涉及的物体和图像区域。
- 判断缺陷严重程度。
- 确定改进优先级。
- 说明判断证据与不确定性。

人类不需要审查 Blender 代码，不需要提供技术解决方案。

视觉评价必须以参考图忠实度为目标，而不只是让场景更漂亮。

## B2. 教师的三个逻辑模块

Perceptual Critic：

仅查看参考图与重建图，评价人类可见缺陷和相对重要性。

Technical Diagnostician：

额外查看学生 Blender 代码、实际三维状态和执行轨迹，提出技术原因假设。

Exploration Teacher：

根据诊断设计不同 Hint、竞争假设、探索方法和验证方案。

初期可以使用同一个模型承担不同逻辑角色。

允许未来技术诊断具有两个模式：

- 无 GT：只能检查学生场景和参考图。
- GT 辅助：额外访问开发场景完整 GT。

视觉对齐评价本身不使用完整 Blender GT，保证教师可以分析任意真实参考图片。

技术诊断和知识学习可以使用 GT，但不能将 GT 不可见部分的差异直接当作人类视觉缺陷。

## B3. 初始教师对照

### T0：原始教师

使用简洁的通用重建评价指令。

不提供人工评价案例，不预先指定目标缺陷。

### T1：人类原则指导教师

提供用户已经明确表达的初步评价原则：

对目前几个场景，人类认为物体位置、朝向、空间关系及材质贴图比轻微支撑间隙更加影响整体恢复度。

这条原则应作为参考，不得固化成所有场景的绝对权重。

T1 只能称为人类原则引导，不能称为已完成正式人类对齐。

### T2：人类案例学习教师

在获得真实人工评价后，利用开发标注案例提炼人类判断原则，或检索相关案例进行辅助评价。

### T3：诊断机制演化教师

在获得真实人工评价后，根据 T0/T1/T2 与人类之间的实际差异，改进教师的 Critique Skill、检查流程、证据使用和缺陷优先级策略。

基础模型权重固定。

所有教师版本采用相同的任务输入与合理匹配的推理预算。

在正式人类反馈尚未提供时，仅实际运行 T0 和 T1，并准备 T2、T3 所需接口和后续实验流程。

不得自动生成虚构的人类标签来启动 T2/T3。

## B4. 初始标注材料

利用 Experiment 01 的九个真实重建结果，以及 Experiment 02 的三十个真实修改结果。

优先选择约12–18个具有代表性的开发与独立评价案例，尽量减少人类标注成本。

开发案例优先包含：

- 相机改善但物体布局仍不合理。
- 投影改善但潜在三维结构退化。
- 材质实现改变但外观改善有限。
- 自动指标与视觉判断可能不一致。
- 不同建模方法产生相近效果。
- 人类可能更关注位置、朝向和材质的案例。

不能只选成功案例。

独立评价案例来自未参与教师调整的新参考场景。

按场景分组，不允许同一个参考场景的不同版本分别进入严格开发和测试集合。

已有三个场景已被用户观察过，优先作为开发数据，不宣称它们是严格独立的人类评价测试集。

如果需要新生成少量评价结果，使用原始 Scene Harness，不提供学习后的能力库，以避免与03-A互相污染。

## B5. 人类评价界面

复用已有匿名 HTML 评价页面，进一步简化。

每个案例展示真实参考图和匿名重建图。

隐藏实验组、教师评分、GT 信息、自动指标和预期结果。

人类可以提供：

1. 整体恢复度：0–100，粗粒度评分即可。
2. 同一参考图下的相对偏好：A 更好、B 更好、相近或无法判断。
3. 最重要的1–3个视觉缺陷。
4. 简单自然语言描述，可选。

缺陷类别包括：

- 物体识别与遗漏。
- 相对位置及布局。
- 物体朝向。
- 相对比例。
- 几何和部件连接。
- 材质与贴图。
- 相机与构图。
- 光照与阴影。
- 其他。

不要要求人类提供 Blender 技术原因。

提供本地 JSON 导出功能。

开发标注与独立测试标注应分开导出，后者不能进入教师调整过程。

## B6. 自动教师基线

在取得人类标注前，先运行并保存 T0、T1 的真实判断。

不向教师预先指出每张图的错误目标。

要求教师独立输出：

- 整体恢复度估计。
- 主要可见缺陷。
- 对应物体和图像区域。
- 严重程度。
- 改进优先级。
- 判断置信度。
- 证据与不确定性。

采用真实图像输入，不能使用另一模型的图像描述替代。

保存实际模型请求和完整原始输出。

这些预测先冻结，不根据之后的人类评价回改初始教师结果。

## B7. 后续真实人类对齐

在用户返回开发标注之后：

- 比较人类与 T0/T1 的判断差异。
- 构建 T2 案例学习教师。
- 基于开发反馈提出 T3 教师诊断流程更新。
- 使用独立选择数据验证候选。
- 冻结教师版本。
- 在未参与调整的新场景上与独立人类判断比较。

评价指标：

- Spearman 或 Kendall 排序相关性。
- 相对偏好一致率。
- 缺陷识别一致性。
- Top-k 重要缺陷覆盖率。
- 缺陷严重程度和优先级一致性。
- 人类标注成本。
- 教师模型调用和时间成本。

单个用户提供的评价只能支持与该评价者的判断对齐。

未来如需宣称一般人类偏好对齐，需要增加独立评价者及一致性研究。

不要等待人工回复而阻塞03-A。
