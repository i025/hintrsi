# 下一阶段主动探索的真实案例

这些是实验结束后的自动化助手分析，不是人类标注，也没有反馈给任何正式学生。事实、解释假设和后续候选干预分别记录。图像见 `human_review/comparison.png`；代码与工具事件均保存在各运行目录。完整标签证据见 `annotations.json`。

## C01：相同椅子策略与重复的支撑间隙

**事实。** S01 三次都用自建座椅曲面、Subdivision、Solidify、柱体和五辐底座。三次轮子均以默认竖直轴圆柱生成。整个椅子组件的最低几何位置高于全部地板几何的最高位置，间隙分别为 0.015、0.0095、0.027 个学生场景坐标单位。这里不是拿学生坐标与 GT 直接相减，也没有用包围盒相交冒充接触；严格的正垂直分离本身排除了接触。

**证据。** S01-R1 `build.py:55–75`、R2 `:64–82`、R3 `:56–74`；各运行 `analysis/technical/capture/final_state.json`；`support_separation.json` 列出参与比较的全部真实对象。三次参考图/渲染见比较图第一行，额外视角在各运行 `analysis/technical/capture/view_*.png`。

**假设。** 相似的轮子中心、高度与半径写法可能忽略了真实接触面；不是凭本次三次重复就能认定基础模型不具备接触建模能力。

**后续候选。** 比较“强调支撑接触自查”和“强调轮子/底座结构”的不同教师引导。当前实验没有执行任何这种引导。

## C02：卧室床体的重复悬空与未恢复的地毯纹理

**事实。** 三次床体都由独立床座和床垫箱体组成，保存的几何没有补足床体到地板/地毯的支撑。严格垂直间隙为 0.0425、0.0825、0.119 个学生坐标单位。三次地毯材料均为常量 Principled 材料；名称出现“mottled”并不代表实际实现了斑驳纹理。

**证据。** S02-R1 `build.py:59–63`，R2 `:63–67`，R3 `:52–56`；`support_separation.json`；三次最终场景节点列表与比较图第二行。没有把右前景的隐藏部件差异当成已确认错误。

**假设。** 床体的中心高度和厚度设定可能未与地毯顶面联动；材料名称可能替代了实际纹理实现。现有轨迹不足以证明学生“知道而不会执行”某个完整算法。

**后续候选。** 分别探索支撑关系检查与材质节点检查，而不是把两者混成单一综合质量分。

## C03：不同门结构实现，仍有相近的遮挡恢复问题

**事实。** S02-R1 用手工铰链坐标变换构建门板和装饰；R2、R3 使用 Empty 父对象统一管理门板及装饰。三次都没有恢复参考图中门板占据中央前景的遮挡关系。R3 虽调整相机后构图更接近参考，但其门依然接近侧边条带。层级可编辑性更好不等于图像恢复更好。

**证据。** R1 `build.py:44–52`，R2 `:54–62`，R3 `:64–71`；真实 parent/children 结构；比较图第二行。R3 的相机 Edit 为 `call-aeede64d5e7946c4920301d096ffda04`，之后实际重新执行。

**后续候选。** 比较“门轴/朝向探索”与“相机—遮挡联合检查”的引导。需要独立实验，不能从本次相关性推出因果。

## C04：厨房台面纹理的互补方法

**事实。** S03-R1 使用 Noise→ColorRamp→Principled Base Color，并对 Generated 坐标做各向异性缩放；R2、R3 用细杆几何模拟纹理。R1 还有真实 FONT 时钟对象；R2 为叶片添加 Solidify；R3 用缩放 UV sphere 表现花苞。不是只有参数不同。三个最终结果都可辨认为厨房，但相机、台面外观和地板明暗仍有明显差异。

**证据。** R1 `build.py:9–10,35–36`；R2 `:37–40,73–76`；R3 `:31–33,67`；实际材质节点、Modifier 与对象类型。辅助 SSIM 分别约 0.599、0.595、0.592，不能据此认定人类感知质量等价，也不能单独排出优劣。

**后续候选。** 探索节点材质与几何纹路各自适合的对象、尺度和视角；探索把时钟细节、叶片厚度与合理材质组合的可能性。本次未合并学生结果。

## C05：确实观察并修改，但修复范围有限

**事实。** 六次运行读取过自渲染并修改了相机。S03-R2 还把三盏面积光的能量从 600/330/250 改为 350/180/120，之后实际重渲染。其他五次修订仅改相机。所有这些修订没有改变已经建立的几何或材质。轨迹没有显示对上述椅子、床体支撑间隙进行检查或修复。

**证据。** 每次实际 Blender 调用前的 `capture/blender_*/code/build.py.diff`；`annotations.json` 中具体工具 ID；S03-R2 Bash `call-7dfefea1951142bd92abd303dde3c87f`。

**辅助变化。** S01-R1 的参考-渲染 SSIM 从 0.564 变为 0.525，S01-R3 从 0.588 变为 0.556；S02-R3 则从 0.578 变为 0.673。修改相机不保证指标单调改善，且这个指标本身不能替代感知判断。真实前后图见 `human_review/revision_comparison.png`，本次没有由控制器挑选并恢复“最好图”。

**边界。** 这支持“图像观察后的修复集中于相机，另有一次光照调整”，不支持“学生完全没看图”“学生知道所有错误却不会修复”或任何隐藏推理叙述。

**后续候选。** 比较不同诊断关注点是否能扩展修复范围，并控制相同调用/时间预算。不能直接把增加教师后的更多推理额度当成知识收益。

## C06：有共同成功细节，也有单图不可辨识性

**事实。** 办公室参考门是两列四行共八块面板，三次学生都构建了八块相关细节，不能把重复误算成错误；图见 `human_review/office-door-detail.png`。厨房三次也都构建了六个灶圈与两个紫色旋钮。

卧室右前景在 GT 中是第二个书架，但 RGB 主要露出截断背板。学生分别使用白色家具板或床端部解释该区域。仅根据单图不能把 GT 隐藏的书架内部结构差异直接认定为错误；因此此项没有计入缺陷复发。

**后续候选。** 先由人类指出“可见部分哪里不对”及优先级，再决定教师是否应关注真实可辨识的缺陷。不要把不可辨识语义变成要求学生猜中数据集生成标签。

## 未找到完整证据的类别

没有找到足以证明“同一个学生明确提出了正确技术但完全没有执行”或“明知错误但已证明不会修复”的完整案例。厨房 R1 会生成程序化纹理，而其他运行没有采用它，只能证明同一基础模型在独立采样中有方法差异，不能冒充单个会话的明确知识状态。没有虚构这两类案例来凑齐清单。
