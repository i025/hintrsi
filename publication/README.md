# 上传整理说明

本仓库从 xymo 用户目录下的三个实验目录及后续方向文档生成，原始目录未修改。

- `file-manifest.json`：每个源文件对应的上传路径、原体积、上传体积、脱敏次数与是否追加 gzip 包装。
- `excluded-files.json`：未复制的环境目录、凭据、磁盘、套接字等；目录排除表示整个子树不在上传范围。
- `summary.json`：文件数、体积及脱敏统计。
- `verification.json`：整理后的内容复查结果。

代码、配置、历次成绩、失败和中断记录、Hint、补丁、完整对话/工具轨迹、Token/耗时账本、预检材料及源码快照均保留。`runs/` 和 `preflight/` 包含不同性质的记录，请按配置和状态区分。未另外复制与本项目无关的 xymo/rsi 目录。

未上传的内容包括：虚拟机磁盘和引导镜像、已安装 Python/SDK/QEMU/Docker 程序、依赖缓存、运行时套接字、私钥、认证状态和 CLI 本地账号数据库。它们不属于实验结果；环境启动脚本和状态元数据仍保留。没有把符号链接指向的账号文件复制进来。

凭据使用 `REDACTED_CREDENTIAL` 替换，包括本机代理口令在历史状态中的副本。归档内部也经过检查和脱敏；部分运行时/凭据成员从归档中排除并单列记录。归档可能重新打包，因此旧快照大小或校验信息仅作历史参考；行为参数与成绩没有因上传而重新采样。

大于 4 MiB 的未压缩文件追加 `.gz`；原先已经压缩的归档保持其文件名。路径和名称没有做其他整体重排。可先查看 `file-manifest.json` 的 `gzip_wrapped` 项，再按需解压：

```bash
gzip -dk path/to/trajs.json.gz
gzip -dk path/to/model_requests.jsonl.gz
```

历史文档或程序对原文件名的引用未批量改写；查看日志或重新分析时，应使用映射找到 `.gz`，并在自己的分析副本中解压。不要将旧的绝对服务器路径和保存的运行状态当作新机器的配置。
