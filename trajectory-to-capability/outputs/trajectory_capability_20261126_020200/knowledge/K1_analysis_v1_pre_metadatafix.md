## Lessons from the development trajectories

The eight observations illustrate several different outcomes, not a single progression. D05 received formal reward 1; the other seven received reward 0. That distinction matters even where an agent committed code or reported passing checks. The cohort contains no evidence from Selection or Test, and truncated output cannot establish what its omitted portion said.

**Delegation and provider boundaries.** D01 inspected the handler, provider contracts, registry, and tests, and reported that delegation was not executed. It created a branch but stopped without source changes because the invoked skill required clarification when it encountered non-Anthropic provider markers (D01 events 1–3, 7–8, 17–20, 29). D04 similarly stopped and asked for clarification, with an empty patch (D04 events 1–6). These are instruction-bound interruptions, not failed implementations or evidence that the diagnosis was wrong. D03 separately reported a read-only permission constraint and made no changes after initial inspection (D03 events 1–7); that is a permission-based refusal, not an implementation test.

The supplied teacher material for the delegation task framed the problem as an execution-and-feedback round trip across a handler, a provider-neutral interface, and a provider adapter. It also emphasized bounded recursion, path-local cycle checks, preserving stream attribution, and verification beyond a happy path. These are proposed directions rather than observed correctness. The later D03 reference additionally warned that a global registry is not the same as request-specific authorization; D03 did not implement or test that warning (D03 events 4–7 and supplied teacher material). The reference’s instruction to verify clues against the actual project is itself reusable: source inspection can confirm where a proposed direction applies, while applicable permissions and skill instructions still govern whether work can proceed.

D02 visibly adopted several ideas consistent with that material: it inspected interfaces, made a failing public-handler reproduction, then extended contracts and changed handler and adapter behavior (D02 events 4–25, 30–53). The reproduction failed before the changes and passed afterward (events 31–33, 59–61). That is meaningful evidence for one continuation scenario, not a full pass: type-checking failed on a missing generated file, unit tests and cleanup were outstanding, and the changes were uncommitted (events 54–62). Formal reward was 0. In particular, the visible handler edit offered a tool without demonstrating capability gating or request-specific target availability (event 40); a focused reproduction cannot establish those properties.

D05 provides the clearest example of **observable online-teacher adoption**, without proving causality for the overall result. After the teacher prompted inspection of a request containing both prior context and new input, the agent’s mocked request showed that its change dropped the new instruction and image; it revised the continuation handling and later inspected both initial and continuation messages (D05 online teacher check 1; events 49–57, 95–98). A second teacher prompt asked for feedback and identity checks beyond call counts. The subsequent mocked checks inspected successful multi-chunk feedback, worker failure, and an unknown agent, including matching tool identity (online teacher check 2; events 84–85). A separate circular case passed (events 108–109). These checks show adoption of the requested verification approach, not complete coverage of nested behavior or every adapter edge case.

D05 also demonstrates why environment and regression evidence should be reported separately. Its initial type-check attempts encountered a wrong script location and a missing generated file; generation from the appropriate directory preceded a passing type-check (events 62–71). The handler suite still failed, and the agent reported the same abort-cleanup failure on the baseline; the baseline comparison command’s final shell status alone would not prove that because it also restored a file after the test (events 81–93, 112). The OpenAI suite was blocked by a test transform error (events 99–101). The change was committed and received formal reward 1, but neither that reward nor the mocked checks establish universal provider compatibility (events 110–112). The visible adapter edit, for example, retained malformed streamed input as a string rather than proving comprehensive malformed-stream handling (event 42).

**Persisted data contracts.** The feature-schema teacher material distinguished an ordered raw-input contract from the transformed model width and cautioned that saving raw selection does not persist preprocessing transformations. It proposed tracing training, loading, inference, export, and the API together. D07 inspected those areas but, finding neither a local nor remote requested base branch, asked for confirmation and made no patch (D07 events 2–18). This is an explicit base-branch blocker despite the available technical guidance.

D06 had no supplied teacher hints. It established that the available baseline was `master`, created a branch from it, and made changes across schema construction, application, persistence, error propagation, and export (D06 events 3–20, 27–54). That base substitution was disclosed, not confirmed by the user. Its existing tests failed from the repository root and passed when run from the test directory (events 57–63); the test source itself changes directories, so working-directory-dependent configuration is a plausible and observable concern (event 22). Targeted commands then exercised aliases and broader model/API paths, but their long outputs are truncated; their successful command statuses support only what those commands actually asserted, not every advertised behavior (events 68–70, 75–77). D06 committed the change and reported success, yet formal reward was 0 (events 79–81). Passing two existing tests and selected checks therefore cannot be equated with formal success, nor can the missing reason for the formal failure be inferred. The teacher’s preprocessing caveat remains relevant: a raw-column artifact alone is not evidence that fitted encoders, imputers, or scalers are reused.

**Formatter safety and scope.** D08 first established that the existing parser treated the example as unsupported data and reproduced the unchanged formatting (D08 events 18–25, 34–37). Its first integration failed the existing equivalence check because the parser’s data tokens were line-dependent (events 52–53). The agent introduced a separate lexical comparison, then tested formatting and idempotence; an edge-case check exposed expression-spacing and mixed-statement behavior, prompting another edit (events 54–63). The later focused suite passed 177 tests, and the agent reported the larger unit suite passed; the visible large-suite output is truncated, although its tool result was successful (events 58–59, 78–82).

This is useful evidence for reproducing a failure, inspecting parser representation, checking semantic preservation, and testing idempotence. It is not proof that a new lexical equivalence check covers every dialect, comment, quoted construct, or mixed statement. The agent deliberately declined at least one mixed-statement case rather than formatting it (events 60–63, 68–69). Despite a commit and reported test passes, formal reward was 0 (events 80–82). A broad existing suite can pass while a new feature remains incomplete.

## Candidate reusable knowledge

Treat external guidance as a hypothesis to verify in the actual code and under the actual permissions, not as proof or authorization (D01 events 1–3, 29; D03 events 4–7; D05 events 49–57). Establish a before-and-after reproduction through a public boundary, then inspect the data passed across that boundary—not merely a call count or a success message (D02 events 30–33, 59–61; D05 events 84–85).

Preserve distinctions between a capability and its availability in a particular request, between raw data contracts and fitted transformations, and between a formatter’s output shape and its semantic equivalence (D03 supplied teacher material and events 4–7; D06 events 31–35, 75–77; D08 events 52–59). Test error paths, existing behavior, and environmental prerequisites alongside the nominal case. Finally, report formal outcome, observed checks, incomplete work, and constraints independently: the successful formal result in D05 coexists with failing or blocked suites, while committed and locally checked D06 and D08 still received reward 0.
