## Transferable analysis and limits

Across these different tasks, a useful implementation-independent constraint is **continuity of meaning across a boundary**: a resumed conversation, a later dataset, or a reformatted program must preserve the information needed by its consumer. D05’s request inspection and D08’s equivalence failure make boundary representations observable; D06 demonstrates that raw input ordering is a separate concern from model execution. These are analogous constraints, not evidence that the same implementation applies to all three domains.

The strongest observed repair loop is D05’s teacher-prompted input probe → visible omission → explicit state distinction → request inspection. The later identity/error probe complements it by checking the consumer side, not merely invocation count. D08’s safety-check repair addresses a different representation mismatch; its local idempotence and focused tests support only the exercised cases, especially given formal regressions. D06’s directory correction makes the existing test run interpretable, but the two passing tests are not comprehensive evidence for the new contract. D02’s unrun generator is an identified prerequisite, not a verified repair.

Branch creation, formatting tools, cleanup, and commits are workflow operations rather than evidence of semantic correctness. The supplied reference materials are broader than the observed repairs: D03 and D04 did not implement them, and D02’s partial result does not establish that any particular hint caused improvement. D05’s two online hints precede relevant probes, but there is no controlled comparison proving causal benefit. Round and group labels alone do not establish learning across runs.

**Candidate reusable knowledge:** inspect both sides of state transitions; distinguish new input from continuation, raw contracts from transformed representations, and local checks from broad regression evidence; compare failing checks against an appropriate baseline when possible; report permissions and prerequisites separately from program failures.

**Unsupported hypotheses:** that any hint guarantees improvement; that a formal pass establishes complete correctness; that D06’s missing formal case or D08’s four formal failures have a particular cause; that the truncated outputs prove additional tests passed; or that a clarification stop would have become a successful implementation if allowed to continue.
