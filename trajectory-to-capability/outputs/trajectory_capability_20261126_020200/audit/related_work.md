# 近邻工作与创新性边界

核对时间：北京时间2026年11月26日。以下均实际打开 arXiv 摘要页；这是针对本次实验的边界核对，不是完整系统综述，也没有独立复现论文结果。论文中的数值不作为本次实验成绩。

|工作|已经涉及的机制|本次需要避免的贡献表述|
|---|---|---|
|[SceneEvolve / Learning to Code the World](https://arxiv.org/abs/2610.37046)|固定模型、动作语义与执行后端，教师根据开发重建反馈改进可复用 harness；独立场景无需教师。|固定模型的 Scene harness 自改进本身不是新贡献。|
|[Trace2Skill](https://arxiv.org/abs/2603.25158)|从广泛执行轨迹归纳并整合技能，压缩重复失败与变通方法，研究跨模型和分布迁移。|多轨迹总结、持久文本技能及无需更新权重的迁移本身不是新贡献。|
|[SKILL-KD](https://arxiv.org/abs/2607.28048)|对比同题学生失败与教师轨迹，提取技能补丁，重跑学生并维护有来源的编辑历史。|成功/失败对比、技能补丁、学生验证及合并删除知识本身不是新贡献。|
|[SkillGen](https://arxiv.org/abs/2605.10999)|对成功和失败轨迹做对比归纳；以技能作为干预，同时统计修复和退化。|用同题有/无技能配对评价净收益，或混合成功失败证据，不可直接宣称新颖。|
|[Socratic Skill Learning](https://arxiv.org/abs/2610.17860)|专家指导与学生实践交错；学生操作环境、质疑并检验建议；使用新会话检验迁移。|有效 Hint 不等于长期能力、主动实践与后续独立迁移验证，已有明确近邻。|
|[Teaching the Harness](https://arxiv.org/abs/2611.13144)|建立学生经验画像和限制假设，进行诊断探测，并以匹配开发任务的改善决定技能准入。|面向学生的诊断、能力库验证及教师离开后的保持，不能单独作为新贡献。|
|[DoVer](https://arxiv.org/abs/2512.06749)|通过有针对性的干预验证调试假设；多个不同干预可能独立修复同一失败。|从轨迹提出诊断假设不等于因果定位；本次事后分析不能声称完成反事实验证。|
|[GEPA](https://arxiv.org/abs/2507.19457)|利用轨迹与自然语言反馈反思、提出并测试提示更新，组合互补经验。|反思式提示进化及互补经验组合本身不是新贡献。|
|[SimWorld Studio](https://arxiv.org/abs/2605.09423)|编码代理根据编译、物理检查和视觉批评修复三维环境并增加可复用工具/技能。|将执行反馈和可复用技能迁移到三维生成，不足以直接形成独立新颖性主张。|

本次可检验的具体差别是：在相同原始轨迹、相同提取模型与调用机会、受限文本长度及相同学生预算下，先构造带事件依据的程序状态变化，再按功能目标、行为约束和验证类别对齐，是否比普通顺序轨迹总结更有利于独立跨任务求解。该问题仍与上述对比归纳、诊断与提示进化工作相邻。必须结合真实终测与行为证据判断；即使出现个别改善，也不足以证明状态对齐的普遍优势或宣称“首次”。
