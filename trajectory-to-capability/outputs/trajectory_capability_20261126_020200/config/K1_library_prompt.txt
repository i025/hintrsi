## Candidate reusable knowledge

Treat supplied guidance as hypotheses to check against actual interfaces and behavior, and distinguish a visible adoption from inferred causation. Trace a feature across its boundaries: a streamed operation may require execution, feedback, continuation and stable identity, while a data-model feature may require an artifact, consistent input ordering and clear errors at each entry point (D02 events 24–33, 59–61; D05 events 84–85; D06 events 31–38, 68–77).

Prefer a failing reproduction followed by checks of observable outputs and downstream inputs, not merely a call count. Inspect both normal and error paths, compare failures with an appropriate baseline, and account for generated files and working directory when interpreting test results (D05 events 27–28, 49–50, 67–71, 84–85, 92–97; D06 events 57–63). For formatters, verify semantic preservation and repeated formatting as separate properties, including inputs outside a simple example (D08 events 52–63, 68–69).

Finally, report the exact scope of evidence: formal success is distinct from a partial pass, an empty patch, an environmental or technical interruption, and a request for clarification. Truncated output, unrun tests and guidance without observable adoption do not establish unseen results (D01 event 29; D02 events 56–62; D03 event 7; D05 events 101–112; D07 event 18; D08 events 78–82).
